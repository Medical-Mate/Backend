

# ─── 형식 ────────────────────────────────────────────────
# <타입>: <제목>
#
# <본문 — 무엇이 아니라 왜. diff에 없는 것을 쓴다>
#
# Refs: #<이슈번호>        ← 연결된 이슈가 없으면 이 줄을 지운다
#
# ─── 타입 (여섯 개 중 하나) ──────────────────────────────
# feat      새 기능 추가
# fix       버그 수정
# refactor  동작 변화 없는 구조 개선
# docs      문서, 주석 변경
# test      테스트 코드 추가·수정
# chore     빌드 설정, 의존성, 스크립트
#
# 애매하면: "이 변경으로 사용자가 보는 동작이 달라지는가?"
#   달라진다 → feat / fix
#   아니다   → refactor / chore
#
# ─── 규칙 ────────────────────────────────────────────────
# · 제목은 50자 이내, 한글, 명령형 (~추가, ~수정)
#   "~했음", "~합니다" 는 쓰지 않는다
# · 제목 끝에 마침표를 붙이지 않는다
# · 한 커밋에는 하나의 논리적 변경만 담는다
# · 변경 이유가 확인되지 않았다면 추측해서 채우지 않는다
#
# 규칙을 직접 확인하고 싶으면 (선택):
#   .github/scripts/check-commit-messages.sh origin/main HEAD
