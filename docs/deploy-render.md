무료 플랜 기준입니다. 대시보드에서 하는 일과 저장소가 이미 해둔 일을 나눠 적습니다.

Render를 고른 이유는 **HTTPS 도메인을 그냥 준다**는 점입니다. 카카오 Redirect URI는 80/443만 받아서, 이게 안 되면 로그인이 끝까지 돌지 않습니다.

---

## 절차

### 1. Blueprint로 서비스 만들기

Render → **New** → **Blueprint** → 이 저장소 선택.

`render.yaml`이 웹 서비스와 PostgreSQL을 같이 정의합니다. 대시보드에서 손으로 만들지 않는 이유는, 클릭은 기록이 남지 않아 무엇을 어떻게 설정했는지 나중에 알 수 없기 때문입니다.

DB 접속 정보(`DB_HOST`·`DB_PORT`·`DB_NAME`·`DB_USERNAME`·`DB_PASSWORD`)와 `JWT_SECRET`은 Render가 자동으로 채웁니다.

### 2. 직접 넣어야 하는 값

`render.yaml`에 `sync: false`로 표시된 것들입니다. 비밀값이라 저장소에 두지 않습니다.

| 키 | 값 | 없으면 |
|---|---|---|
| `KAKAO_APP_ID` | 콘솔 주소창의 `/console/app/<숫자>` | **서버가 안 뜹니다** |
| `KAKAO_ADMIN_KEY` | 앱 설정 → 앱 키 → Admin 키 | 탈퇴 시 카카오 연결 끊기만 건너뜁니다 |
| `PUBLIC_BASE_URL` | 배포 후 받은 주소 (아래 3번) | 공유 링크가 잘못된 주소로 만들어집니다 |
| `AI_BASE_URL` · `AI_INTERNAL_TOKEN` | AI 서비스 배포 위치가 정해지면 | 지금은 스텁이라 비어 있어도 동작합니다 |

`KAKAO_APP_ID`와 `JWT_SECRET`은 **없으면 기동 자체가 실패합니다.** 조용히 넘어가지 않습니다 — 둘 다 없을 때 그냥 통과시키면 방어선이 꺼진 채로 로그인이 멀쩡히 성공해서 아무도 눈치채지 못하기 때문입니다.

### 3. 주소 확인하고 되먹이기

첫 배포가 끝나면 `https://jinryomate-backend-xxxx.onrender.com` 형태의 주소가 나옵니다.

1. 그 값을 `PUBLIC_BASE_URL` 환경변수에 넣습니다
2. 저장하면 자동으로 재배포됩니다

이 값은 공유 링크(`/s/{token}`)를 만들 때 앞에 붙습니다. 틀리면 링크가 열리지 않습니다.

### 4. 카카오 Redirect URI 등록

카카오 개발자 콘솔 → **카카오 로그인** → **Redirect URI**에 배포 주소를 등록합니다.

- **글자 하나까지 정확히** 같아야 합니다. 끝의 `/` 하나 차이로도 `KOE006`이 납니다
- 포트는 **80/443만** 됩니다. Render 주소는 443이라 그대로 됩니다

### 5. 확인

```bash
curl -i https://<주소>/api/health
```

- `200`이고 `X-Request-Id` 헤더가 있으면 정상입니다
- 첫 요청은 느립니다 (아래 참고)

API 문서는 **운영에서도 열려 있습니다.** 앱·AI 담당자에게 이 주소를 주면 됩니다.

```
https://<주소>/swagger-ui.html
```

문서가 열려도 엔드포인트는 여전히 JWT를 요구합니다. 드러나는 것은 어떤 API가 있는지이지 데이터가 아닙니다.

## 알아둘 것

### 15분 유휴 후 잠듭니다

무료 웹 서비스는 요청이 없으면 잠들고, 다음 요청에서 다시 뜹니다. **첫 요청이 수십 초 걸립니다.**

**발표 직전에 미리 한 번 깨워두세요.** 시연 첫 화면에서 로딩이 멈춰 있으면 곤란합니다.

### DB는 30일 뒤 삭제됩니다

무료 PostgreSQL 인스턴스는 일정 기간(현재 30일) 뒤 삭제됩니다. **데이터가 지워지고 접속 정보가 바뀝니다.**

- 스키마는 Flyway가 새로 만들므로 손댈 게 없습니다
- 환경변수만 다시 연결하면 됩니다 (Blueprint를 쓰면 자동)
- 지워질 데이터는 테스트 계정뿐이라 실질적인 손해는 없습니다

**발표가 만료일 이후라면 Neon 같은 곳으로 옮기세요.** 옮기는 비용은 환경변수 몇 개입니다.

### 메모리는 512MB입니다

`Dockerfile`이 `MaxRAMPercentage=65.0`으로 잡혀 있습니다. 힙 밖에서 메타스페이스·코드캐시·스레드 스택으로 150~200MB가 나가기 때문입니다.

75%로 올리면 합계가 한도를 넘어 **OOM으로 죽습니다.** 로그도 안 남고 재시작만 반복해서 원인을 찾기 어렵습니다.

파일 업로드를 받지 않으므로 힙에 올라가는 가장 큰 객체는 카드 JSON 몇 KB입니다. 그래도 OOM 재시작이 보이면 힙 비율이 아니라 플랜을 올려야 합니다.

## 문제가 생기면

| 증상 | 원인 |
|---|---|
| 기동 로그에 `KAKAO_APP_ID 가 필요합니다` | 환경변수 누락 |
| 기동 로그에 `JWT_SECRET 이 필요합니다` | 환경변수 누락 |
| 헬스체크 실패, 로그는 정상 | 포트 문제. `server.port`가 `${PORT:8080}`인지 확인 |
| 재시작만 반복, 로그 없음 | OOM. 힙 비율을 낮추거나 플랜을 올립니다 |
| 로그인 시 `KOE006` | Redirect URI 불일치. 글자 하나까지 맞춰야 합니다 |
| 로그인 시 401 | `KAKAO_APP_ID`가 틀립니다. 앱 ID는 숫자입니다 (32자리 키가 아닙니다) |
| 공유 링크가 안 열림 | `PUBLIC_BASE_URL`이 배포 주소와 다릅니다 |
