# 진료 하루 전 알림 — 앱이 예약합니다

**서버는 푸시를 보내지 않습니다.** 앱이 일정을 받아 기기에 로컬 알림을 예약합니다.

## 왜 이렇게 정했나

Render 무료 플랜은 **15분 유휴 후 컨테이너가 내려갑니다.** 진료 하루 전 알림은 사용자가 앱을 안 쓸 때 나가야 하는데, 그때가 바로 서버가 자는 시간입니다. **서버 안 스케줄러(`@Scheduled`)로는 알림이 아예 안 갑니다.**

외부 크론으로 서버를 깨우는 방식도 되지만 Firebase 프로젝트·서비스 계정 키·앱 SDK가 선행됩니다. 3주 일정에서 그 비용이 큽니다.

---

## 앱이 쓸 것

```
GET /api/me/appointments/upcoming
```

아직 안 지났고 취소되지 않은 일정이 가까운 순으로 옵니다.

```json
[
  {
    "appointmentId": 1,
    "clinicName": "서울OO병원",
    "department": "내과",
    "purpose": "재진",
    "scheduledAt": "2026-09-12T01:30:00Z",
    "status": "SCHEDULED",
    "cardId": 3,
    "cardTitle": "복부 통증 · 3주"
  }
]
```

**알림 예약에 필요한 것이 다 있습니다.** 문구는 이 필드로 앱이 만듭니다.

```
"서울OO병원 내과 재진"        clinicName + department + purpose
"내일 오전 10:30 이에요"       scheduledAt (사용자 시간대로 변환)
"복부 통증 브리핑 카드 준비됐어요"  cardTitle
```

## 언제 다시 예약하나

| 시점 | 왜 |
|---|---|
| 일정을 만들거나 고친 직후 | 앱이 방금 만든 것이라 즉시 압니다 |
| 앱을 열 때 (`upcoming` 호출) | 다른 경로로 바뀐 일정을 따라잡습니다 |
| 일정을 지웠을 때 | 예약도 취소해야 합니다 |

**`scheduledAt`은 UTC(`Z`)로 옵니다.** 사용자 시간대로 변환해서 예약하세요. 그대로 쓰면 9시간 어긋납니다.

## 서버가 만들지 않는 것

- **알림 문구** — 말투를 바꿀 때마다 서버를 배포해야 합니다
- **D-day·"n일 남음"** — 서버 시간대와 사용자 시간대가 다르면 하루 틀립니다

홈 요약(`GET /api/me/home`)도 같은 규칙입니다. 숫자와 날짜만 주고 문장은 앱이 만듭니다.

---

## 한계 — 알고 쓰셔야 합니다

**여러 기기 동기화가 안 됩니다.** A 기기에서 만든 일정의 알림은 A에서만 울립니다. B 기기는 앱을 열어 `upcoming`을 받은 뒤에 예약합니다.

**기기를 바꾸면 예약이 따라가지 않습니다.** 새 기기에서 앱을 처음 열 때 다시 예약됩니다.

데모 규모에서는 문제가 되지 않습니다. 실제 사용자를 받게 되면 서버 푸시로 옮깁니다.

## 서버 푸시로 옮길 때

`POST /api/me/devices`(푸시 토큰 등록)가 **이미 만들어져 있습니다.** 지금은 부를 필요가 없지만, 옮길 때 그대로 씁니다.

그때 필요한 것:

1. Firebase 프로젝트 + 서비스 계정 키 → Render 환경변수
2. 앱에 FCM SDK
3. 외부 크론(`cron-job.org` 등)이 매일 발송 엔드포인트를 호출 — **또는** 유료 플랜으로 올려 `@Scheduled` 사용

유료 플랜으로 가면 3번이 사라집니다. **배포 플랜을 바꾸는 시점에 같이 검토하는 게 맞습니다.**
